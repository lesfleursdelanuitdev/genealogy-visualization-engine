## API changes so far (for the CHANGELOG, step 7)

**Added:** `createGraphSnapshot`, `GraphSnapshot`, `GraphInput`, `SnapshotUnion`, `SpouseLink`, `EMPTY_GRAPH`, `unionIdOf`; `createChartSession`, `ChartSession`, `ChartSessionInit`, `ChartSessionOptions`, `ChartLayout`, `layoutChart`, `isGraphSnapshot`; `createTreeReducer`; `BuildTreeResult` exported; `useChartViewFetch` returns `graph`.

**Changed (breaking):**
- `buildTree(rootId, strategy, { graph, maxDepth, getHiddenCount })`: `graph` is required. `BuildContext` has `graph`; `people` is a `ReadonlyMap`.
- `treeReducer(state, action, graph?)`: without a graph, data-dependent actions do nothing.
- `countDescendants(graph, personId)`, cached per snapshot. `ViewStrategyDescriptor.getHiddenCount(graph, personId)`.
- `isAllSpousesRevealed(graph, revealedUnions, rootId?)`, `buildLegendItems(graph, …)`, `HandlePersonCardActionContext.graph` (required), `useDepth({ graph })` (was `builder`).
- `ChartViewBuildAdapter` has `graph` instead of `getDataBuilder()`.
- `main`/`types`/`exports` point at `dist/` (only `.` and `./package.json`; the `./*` → `src/*` subpath export is gone).
- Unions without an id get `husb-wife` everywhere (the catch-all used `""` before and treated them as revealed).

**Removed:** `FamilyTreeBuilder` (+ `FamilyTreeBuildOptions`, `FamilyTreeBuilderInput`), `setCurrentBuilder`, `clearCurrentBuilder`, `setCurrentTreeData`, `clearCurrentTreeData`, the eight global getters (`getPeople`, `getUnions`, `getUnionsByPerson`, `getAllChildrenOf`, `getParentUnionsByChild`, `getUnionById`, `getBirthUnionByChild`, `getSpousesOf`: use the graph's fields and methods), `clearDescendantCountCache`, `buildView`, `FamilyTreeNodeFactory` (+ config, descriptors), `useDescendancyFetch`, `getAllActionTypes`, `serializeNode`, test data (`buildTestTree`, `UNIONS`, `*_BY_*`, `PEOPLE_WITH_*`), and from the index only: `DescendancyChartAdapter`, `PedigreeChartBuilder`, `VerticalPedigreeChartBuilder`, `FanChartBuilder`, `PedigreeViewStrategy`.

**Of the 92 exports the app doesn't use**, the rest are kept as renderer/viewer API: layout, bounds and connector helpers, fan geometry, node classes and types, the strategy and layout option types, `UnionRecord`/`UnionChild`/`LinkedUnionEntry`, `CHART_VIEW_STRATEGIES`, `computeFitToViewport` and the hook option/result types. `DEFAULT_ROOT_XREF` stays until step 4 removes the default root.

**Gonsalves migration (step 6) will need:** `graph` from `useChartViewFetch` into `createTreeReducer`, `useDepth`, `handlePersonCardAction` and `buildLegendItems`; the global getters replaced by `graph.*` (18 imports across the app's files, counted by name); `isAllSpousesRevealed(graph, …)` (2 files).

## Decisions taken in this run

- **Extra dev dependencies:** `react-dom` 19.2.4 (must equal the locked `react` 19.2.4; the app has 19.2.3 of both), `jsdom` 30.1.3 (no install scripts) and `@types/react-dom` 19.2.3 (app's version), for the hook repros (H2, B01, B02, B07, B08, B14, B15, S3). No testing-library: a 60-line harness in `test/helpers/renderHook.ts`.
- **vitest 4.0.18** matches the app but `npm audit` flags it (GHSA-82fw-gwwq-j7x9 moderate, GHSA-qxg6-89mg-rqv8 critical; fixed in 4.1.11). Both concern vitest's mock/server API; we only run `vitest run`. The app has the same version.
- **`dist/` is bundler-only ESM:** the source's imports have no extensions, so `tsc` emits them as is. Fine for Vite, Next and vitest; bare Node ESM can't load it.
- **Test data** lives in `test/fixtures/smith`, outside the package. `test/boundaries.test.ts` fails if `src/` imports it, mentions a current builder, or has a module-level `let`/`var` outside `debug/`.
- **Sessions take `{ people, unions }` or a snapshot.** A session over 70,000 people should get the snapshot, built once per file, so a view-state change doesn't rebuild the indexes.
- **Not touched yet:** the `unknownPerson` "Unknown" placeholder rule, `isLiving` mapping, the default root, `process.env`, console logs: all belong to steps 4 and 5 and have repros.
